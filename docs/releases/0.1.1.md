# Mercado Pago Terminal for WooCommerce 0.1.1

This release follows the first run against a live Mercado Pago account and a physical Point Smart terminal (a Chilean-peso shop, 2026-10-15). Listing terminals, switching the terminal to PDV mode, creating an order for the terminal, polling it and cancelling it through the API all worked; the order was created with the amount fix in this release. A real card payment on the terminal, the webhook on a paid order, and refunds have not been exercised yet.

## Fixed

- Shops that price in whole units (WooCommerce "Number of decimals" set to 0, as with Chilean pesos) now send whole-unit amounts such as `100`. Mercado Pago refused `100.00` on such an account with "does not match pattern", so no order could be created. Shops with 2 decimals send the same amounts as before.
- An order Mercado Pago reports in a different currency from the WooCommerce order is no longer completed.
- Error messages from Mercado Pago now include its details, so a rejected order names the field that was refused instead of only "Invalid value for property".
- The log and the support bundle now report the WooCommerce POS version instead of `n/a`.

## Upgrade

Update the plugin. Then check **WooCommerce → Settings → General → Number of decimals**: if your shop takes Chilean pesos, or another currency Mercado Pago refuses with decimals, it must be **0**. The plugin only sends whole-unit amounts when that setting is 0; with 2 decimals the request is still refused. After that, a payment that failed with "Invalid value for property" should be accepted by Mercado Pago and sent to the terminal. Whether it then shows on the terminal screen and can be paid has not yet been seen.
