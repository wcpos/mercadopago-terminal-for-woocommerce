# 1.0.0 — Pro shared payments base

Requires WooCommerce POS Pro 2.0+, WooCommerce, WordPress 6.0+, and PHP 7.4+. This release belongs to `next`; `main` remains 0.x.

## Changes

- Real MP Orders-API adapter for Pro server payments and the shared order-pay panel.
- Pro-managed reader selection, lifecycle, signed webhook route, refunds, logging redaction, and support bundle.
- Legacy live-attempt adoption under Free's order lock; obsolete cron cleared, old metadata retained.
- Historical refunds retain the `ORD…` transaction reference and resolve `PAY…` only for partial-refund payloads.
- WordPress-based conformance and focused tests replace all stub and private-panel tests.
- CI mounts sibling Pro `next` with a read-only GitHub App token and runs PHP 7.4/8.3.

## Behavior changes / regressions

Pro 2.0 is now mandatory. Configure the new `/wp-json/wcpos/v2/payments/webhook?provider=mercadopago` endpoint and a secret: unsigned notifications are rejected. Configure readers in Pro; old extension reader settings and browser log controls are ignored. Pro supplies the support-bundle row. The old AJAX endpoints and `mptfwc_order_payload` filter are removed. External refunds do not automatically create WooCommerce refunds.

The test/live selector labels the pasted credential; it does not supply a second token. Finish outstanding attempts before replacing credentials. Store currency must match the seller account's local currency.

## Release evidence and limits

Conformance exercises the real extension through WordPress, WooCommerce, Pro, and Free with only provider HTTP faked. Goldens are in `tests/includes/Conformance/transcripts/`; reviewer approval is required before committing them. Three unsupported capabilities are skipped: prompts, manual capture, final cancellation. A passing transcript is not certification.

No live/sandbox Mercado Pago calls, hardware flows, or hosted GitHub Actions runs were performed. No broad 0.x equivalence or performance claim is made. See README for setup and untested provider behavior.
